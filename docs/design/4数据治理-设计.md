# 四、Zen Metadata 数据治理能力设计

数据治理不是附加功能，而是 Zen Metadata 从
**“记录系统” → “决策与约束系统”** 的关键跃迁。

本章节围绕 **分类与标签、数据标准、数据目录与发现** 三个方面，构建可执行、可演进、可智能化的数据治理体系。

---

## 4.1 数据分类与标签语义体系

### 4.1.1 设计目标

* 为元数据赋予**治理语义**
* 统一业务、技术与合规视角
* 成为质量评估、权限控制、搜索推荐的基础信号

> **标签不是注释，而是治理规则的入口**

---

### 4.1.2 标签模型设计

```python
# src/core/models.py
class Tag:
    id: str
    name: str
    category: str      # 业务域 / 数据质量 / 技术栈 / 合规
    description: str
    color: str         # UI 可视化

class EntityTag:
    entity_id: str
    tag_id: str
    user_id: str
    created_at: datetime
```

标签具备以下特性：

* 可版本化（标签定义可演进）
* 可权限控制（谁能打、谁能删）
* 可审计（谁在什么时候打的）

---

### 4.1.3 多维分类体系

Zen Metadata 支持多正交分类体系并行存在：

#### （1）业务分类

* 销售、财务、运营、风控等
* 面向业务与管理视角

#### （2）技术分类

* 表 / 视图 / API / Topic / 文档
* 面向技术治理与架构分析

#### （3）数据敏感度分类

* 公开 / 内部 / 受限 / 机密
* 与权限、脱敏、审计强绑定

#### （4）生命周期分类

* 开发 / 测试 / 生产 / 归档
* 影响采集策略与变更审批

---

### 4.1.4 自动标签推荐机制

标签不仅可人工维护，也可自动生成：

* **基于实体属性**

  * 字段名、类型、来源系统
* **基于相似实体**

  * 结构相似度 + FalkorDB 图距离
* **基于历史行为**

  * 被哪些人使用、如何使用
* **基于模型预测**

  * LLM / ML 进行标签建议（人工确认）

> 自动标签 **不直接生效**，而是进入“建议态”，进入协作与治理流程。

---

## 4.2 数据标准与规范管理

### 4.2.1 设计目标

* 将“约定俗成”变成“可执行规则”
* 降低治理依赖人工经验
* 为质量评分提供明确依据

---

### 4.2.2 数据标准定义体系

Zen Metadata 将数据标准建模为**可计算对象**：

#### （1）命名规范

* 实体、字段、指标命名规则
* 正则 / 模板 / 词表

#### （2）格式规范

* 日期、时间、编码、枚举
* 跨系统一致性约束

#### （3）质量规范

* 非空率、唯一性、取值范围
* 与质量评分规则绑定

#### （4）关系规范

* 哪些实体可以建立哪些关系
* 防止血缘与依赖的“语义污染”

---

### 4.2.3 规范校验与自动治理

* 元数据采集后自动触发规范校验
* 违规项生成治理事件
* 提供：

  * 修复建议
  * 批量修复能力
  * 人工确认流程
* 输出规范合规性报告

> **治理不是阻断，而是可解释的引导**

---

## 4.3 数据目录与数据发现体系

### 4.3.1 设计目标

* 让用户“找得到、看得懂、用得放心”
* 降低数据使用门槛
* 提升组织数据复用率

---

### 4.3.2 数据目录能力

Zen Metadata 提供统一的数据目录视图：

* 按分类、标签浏览
* 支持多维过滤（系统、质量、生命周期）
* 与搜索、语义检索无缝融合
* 支持收藏、书签、最近访问

数据目录并不是静态列表，而是**个性化视图**。

---

### 4.3.3 智能数据发现能力

数据发现基于多信号融合：

* **使用行为**

  * 谁在用、用得多不多
* **结构相似度**

  * 表结构 / API Schema 相似
* **语义相似度**

  * 向量检索 + LLM
* **血缘关系**

  * 上下游、影响范围
* **质量评分**

  * 推荐“可用的数据”

这些信号最终统一为推荐排序函数：

```text
discovery_score =
  α * semantic_similarity
+ β * graph_proximity
+ γ * quality_score
+ δ * usage_popularity
```

---

### 4.3.4 数据使用分析与治理反馈

* 数据访问频率
* 高价值 / 低使用资产识别
* “影子数据”发现
* 反向驱动：

  * 分类优化
  * 标准调整
  * 质量规则校准

---

## 一句话总结这一章

> **分类与标签定义“它是什么”，
> 标准定义“它应该怎样”，
> 目录与发现决定“它值不值得被用”。**

当这一层完成时，Zen Metadata 已经不只是“描述系统”，
而是一个**持续自我修正的数据治理引擎**。
