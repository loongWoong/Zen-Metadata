
# 三、Zen Metadata 用户权限与协作模型设计

随着 Zen Metadata 从“单用户工具”演进为“组织级元数据平台”，**身份、权限与协作能力成为系统可扩展性与可信度的基础设施**。
本章节从 **认证授权、权限模型、协作机制** 三个层面，构建可治理、可审计、可扩展的用户体系。

---

## 3.1 用户认证与授权体系设计

### 3.1.1 设计目标

* 支持多用户、多团队同时协作
* 保障元数据访问与操作的安全性
* 为审批、审计、责任归属提供身份基础
* 与企业现有身份体系无缝集成

---

### 3.1.2 认证体系设计

Zen Metadata 采用 **多认证方式并存的统一身份层**，满足不同使用场景：

#### （1）内建认证

* 用户名 / 密码认证
* 密码复杂度与有效期策略
* 适用于快速部署与中小团队

#### （2）OAuth2 / OIDC

* 支持 GitHub、Google、企业 SSO
* 无需重复管理用户密码
* 适用于研发团队与云环境

#### （3）API Token

* 面向采集器、自动化任务、CI/CD
* 支持权限绑定与过期控制

#### （4）企业目录集成

* LDAP / Active Directory
* 用户与组织结构自动同步

---

### 3.1.3 会话与安全管理

* JWT Access Token + Refresh Token
* Token 绑定权限快照（避免权限漂移）
* 支持 Token 撤销与失效
* 登录、登出、失败尝试审计

---

## 3.2 权限模型（RBAC + ABAC 混合设计）

### 3.2.1 权限设计原则

> **RBAC 管理“你是谁”，
> ABAC 决定“你现在能做什么”。**

Zen Metadata 采用 **角色 + 规则** 的混合模型，兼顾易管理性与灵活性。

---

### 3.2.2 核心权限抽象

```python
# src/core/auth.py
class Role:
    """角色"""
    name: str
    permissions: List[Permission]

class Permission:
    """权限定义"""
    resource: str   # entity, relationship, collector, job, version
    action: str     # read, write, delete, execute, approve
    scope: str      # all, team, own
```

---

### 3.2.3 权限维度划分

#### （1）资源级权限

* 元数据实体（Entity）
* 关系（Relationship）
* 采集器与插件
* 采集任务与调度
* 版本与审计记录

#### （2）操作级权限

* 读取（read）
* 创建（create）
* 修改（update）
* 删除（delete）
* 执行（execute）
* 审批（approve）

#### （3）范围级权限

* 全局（all）
* 团队（team）
* 个人（own）

---

### 3.2.4 细粒度访问控制（ABAC）

在 RBAC 基础上，引入基于属性的动态权限：

* **实体级权限**

  * 控制单个实体是否可见/可编辑
* **字段级权限**

  * 屏蔽敏感字段（如 PII、密钥）
* **关系级权限**

  * 控制血缘、依赖关系的可见性
* **规则型权限**

  * 基于实体标签、质量评分、系统来源判断

> 例如：
> “质量评分低于 60 的生产表，只允许只读访问”

---

### 3.2.5 权限引擎与执行

* 权限决策集中化（Policy Engine）
* API 层统一鉴权
* 支持策略热更新
* 权限命中结果可审计、可解释

---

## 3.3 协作与知识沉淀机制

### 3.3.1 设计目标

* 让元数据“可讨论、可共识、可演进”
* 把隐性知识沉淀为显性资产
* 支撑跨角色（数据、研发、业务）协作

---

### 3.3.2 元数据评论系统

```python
# src/core/collaboration.py
class Comment:
    entity_id: str
    user_id: str
    content: str
    created_at: datetime
    replies: List["Comment"]
```

* 支持对任意实体发表评论
* 支持线程式回复
* 评论与版本绑定（评论的是哪个版本）
* 支持 @用户 / @团队

---

### 3.3.3 元数据标注与语义增强

```python
class Annotation:
    entity_id: str
    user_id: str
    tag: str
    note: str
```

* 业务语义标签
* 使用注意事项
* 风险提示与经验总结
* 可作为搜索与推荐信号

---

### 3.3.4 变更审批与治理流程

针对关键元数据，引入审批机制：

* 变更前触发审批流程
* 支持多级审批（技术 / 数据治理 / 业务）
* 审批意见与决策记录
* 与版本系统、审计日志自动关联

> **审批不是为了“卡流程”，而是为了“留责任链”**

---

## 3.4 团队与空间模型

### 3.4.1 团队与工作空间

* 支持多团队、多空间隔离
* 空间级别元数据可见性
* 团队级权限模板
* 团队内共享评论、标注、知识

---

### 3.4.2 协作统计与洞察

* 活跃用户与贡献度
* 高频访问实体
* 高风险变更统计
* 团队元数据质量趋势

这些指标将反哺：

* 数据治理决策
* 质量评分权重
* 搜索与推荐排序

---

## 一句话总结这一章

> **权限决定“谁能动”，
> 协作决定“大家怎么用”，
> 审计决定“出了问题找谁”。**

做到这里，Zen Metadata 才真正从：

> **“元数据系统” → “组织级数据认知中枢”**
